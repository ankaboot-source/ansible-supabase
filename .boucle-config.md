# Boucle configuration for ansible-supabase

These GitHub Actions **Variables** (Settings → Actions → Variables) and **Secrets** (Settings → Actions → Secrets) must be set for boucle to work on this repo.

## Variables (non-secret)

| Variable | Value | Why |
|---|---|---|
| `BOUCLE_FORGE` | `github` | Forge type |
| `BOUCLE_DEPLOY_MODE` | `external` | ansible-supabase deploys via its own setup.sh, not via boucle |
| `BOUCLE_REVIEW_MODE` | `diff` | No preview URL; review the diff |
| `BOUCLE_BUILD_CMD` | `ansible-playbook --check --diff playbook-supabase.yml` | Syntax check as "build" (no npm) |
| `BOUCLE_E2E_COMMAND` | `true` | No-op e2e — always PASS. This repo has no live URL and no test suite to run in CI. |
| `BOUCLE_LLM_BASE_URL` | (your LLM endpoint) | OpenAI-compatible API endpoint |
| `BOUCLE_BOT_USERNAME` | `up-bot` | Bot username for forge interactions |
| `BOUCLE_SPEC_PROFILE` | `strict` | Spec validation profile |

## Secrets

| Secret | Value | Why |
|---|---|---|
| `BOUCLE_TOKEN` | (GitHub PAT with repo+issues+PRs+actions scope) | Bot token for forge API calls |
| `BOUCLE_LLM_API_KEY` | (your LLM API key) | API key for the LLM provider |

## Notes

- No `BOUCLE_LIVE_URL` is needed — `BOUCLE_E2E_COMMAND='true'` makes e2e a no-op (always PASS).
- No `BOUCLE_E2E_COMMAND_EVIDENCE_PARSER` is needed — the default evidence block is fine for a no-op.
- The two `.github/workflows/trigger-*-deploy.yml` files are project deploy triggers (NOT ADT) and are preserved.
